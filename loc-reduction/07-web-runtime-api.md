# LOC-Reduction Audit — Web client `runtime/`, `api/`, hooks, et al.

**Scope:** `apps/web/src/{runtime, api, hooks, connection, query-language, domain-cache, mail-state, client-preferences, lib, utils, config}`
**Workspace:** `/home/usr.prj_posthaste/src/.workspaces/reduce-loc` (only repo read)
**Goal:** find ways to shrink hand-written LOC so the client fits AI context better. This is a LOC-reduction audit, not a correctness review.
**Date:** 2026-06-29

## Headline numbers

| Bucket | Files | LOC |
|---|---|---|
| Scoped TS/TSX total | all in-scope dirs | ~17.5k |
| **GENERATED (context-excludable, not hand-trimmable)** | `api/schema.gen.ts` + 2 wasm `.d.ts` | **5398** |
| Test-only helpers shipped in `src/` (relocate, not delete) | `runtime/fakeAdapter*` | 872 |
| Net hand-written LOC genuinely removable (findings below) | — | **~360** |

The single biggest *context* win is excluding the generated OpenAPI schema (5181 LOC) and the generated wasm `.d.ts` (217 LOC) from any AI context window — confirmed generated, see F1/F2. The biggest *hand-written* wins are the dead legacy view-subscription path (F3) and the `unsupportedRuntimeAdapter`/`httpAdapter` boilerplate (F4/F5).

> **Important correction to the prior reviews.** `review-unification.md` §3 and the task brief both point at `apps/web/src/runtime/replica/replicaAdapter.ts` as a 730-LOC TS reimplementation of the Rust `link-core`/`link-replica` fold/diff-inversion. **That file no longer exists.** The fold, diff-capture, and diff-inversion already live in WASM (`posthaste-link-wasm`), reached through the thin `handle.ts` (101 LOC) / `wasmUtil.ts` (92 LOC) boundary. The 730-LOC file is now `entityStoreAdapter.ts`, which is *orchestration* over the WASM handle (open/extend/close view, outbox rehydration/resend, frame routing, count writes) — **not** a fold reimplementation. The "WASM owns the fold" reduction the reviews proposed is, in substance, already done. See "Already done" section.

## Findings

Format: `ID | category | file:lines | EST_LOC_SAVED | risk + behavior-change | how`

### F1 — `api/schema.gen.ts` is generated → context-exclude
- **category:** GENERATED-EXCLUDE
- **file:** `api/schema.gen.ts:1-5181`
- **EST_LOC_SAVED:** 5181 (context exclusion, **not** a source edit)
- **risk:** none / behavior-change: n
- **how:** Header reads `This file was auto-generated by openapi-typescript. Do not make direct changes`. It is the wire schema, regenerated from `openapi.json`. It cannot be hand-trimmed, but it should be excluded from any AI context window (it is pure machine output). Confirm an `openapi-typescript` regen step exists in CI/build so it stays excludable. Only `api/types/*` and `api/conformance/*` reference it via `components['schemas']`.

### F2 — Generated wasm type declarations → context-exclude
- **category:** GENERATED-EXCLUDE
- **file:** `runtime/wasm/posthaste_link_wasm.d.ts:1-190`, `runtime/wasm/posthaste_link_wasm_bg.wasm.d.ts:1-27`
- **EST_LOC_SAVED:** 217 (context exclusion)
- **risk:** none / behavior-change: n
- **how:** `wasm-bindgen` output. The hand-written narrow surface the app actually depends on is `replica/handle.ts`. Exclude the `wasm/*.d.ts` (and the `.js` glue) from context.

### F3 — Dead legacy *view-subscription* path (pre-session-client)
- **category:** DEAD
- **files:**
  - `runtime/subscriptions.ts:1-15` (whole file — `runtimeSubscriptions.view`)
  - `runtime/httpAdapter.ts:307-313` (`openMessageListView`, non-session) + `314-368` (`subscribeView`)
  - `runtime/adapter.ts:31-39` + `:60` (`subscribeView`/`openMessageListView` stubs)
  - `runtime/types.ts` — `subscribeView` & `openMessageListView` interface methods, `RuntimeViewFrame`, `RuntimeViewFrameHandlers`, `RuntimeViewSubscriptionRequest` (~40 LOC of the interface/type surface)
  - (test-side) `runtime/fakeAdapter.ts` `subscribeView`/`openMessageListView` (~30 LOC) + `test/runtimeAdapter.test.ts` cases
- **EST_LOC_SAVED:** ~150 (prod `src/`), +~30 in test helpers
- **risk:** med / behavior-change: n (production-dead)
- **how:** The live read path is the **session** client (`sessionClient.ts` → `runtimeStream` → `subscribeRuntimeFrames`/`openRuntimeSessionMessageListView`). The per-view legacy path (`subscribeView`, the non-session `openMessageListView`, and the `runtimeSubscriptions` facade) has **no production caller** — `runtimeSubscriptions` is imported only by `test/runtimeAdapter.test.ts`, and the non-session `openMessageListView` only by that test + `renderProbe`. Remove the legacy method from `RuntimeAdapter`, all four adapter impls, `subscriptions.ts`, and the dependent tests. Medium risk only because it touches the shared interface + tests; behavior is unchanged because nothing in the app exercises it.

### F4 — `unsupportedRuntimeAdapter` hand-lists every method → `Proxy`
- **category:** BOILERPLATE
- **file:** `runtime/adapter.ts:14-84`
- **EST_LOC_SAVED:** ~60 (71 → ~9)
- **risk:** low / behavior-change: n
- **how:** The stub enumerates all ~50 `RuntimeAdapter` methods, each `() => reject()` (with two special `subscribe*` variants). Replace with a `Proxy` that returns a rejecting function for any property, special-casing the two subscribe methods and the one sync method (`fetchOAuthRedirectUri`). This is `review-unification.md` §4.4. Only reachable for the `'native'` mode, which is itself never produced in production (see F9) — so the whole stub is low-stakes. The type can be preserved with a single `as RuntimeAdapter` cast.

### F5 — `httpRuntimeAdapter` trivial 1:1 delegations → property shorthand
- **category:** BOILERPLATE / DUP
- **file:** `runtime/httpAdapter.ts:369-529`
- **EST_LOC_SAVED:** ~55
- **risk:** med / behavior-change: n
- **how:** ~28 of the tail methods are exact pass-throughs to identically-named imports from `../api/client` — e.g. `createAccount(input) { return createAccount(input) }`, same for `deleteAccount`, `enableAccount`, `fetchAccount(s)`, `fetchIdentity`, `fetchMailboxes`, `fetchMessage`, `fetchSettings`, `fetchSmartMailbox(es)`, `patchSettings`, `patchMailbox`, `previewAutomationRule`, `read`, `resetDefaultSmartMailboxes`, `startProviderOAuth`, `triggerSync`, `uploadAccountLogo`, `verifyAccount`, `updateAccount`, `updateSmartMailbox`, `listPendingOperations`, `discardOperation`, `retryOperation`, `createSmartMailbox`, `deleteSmartMailbox`, `disableAccount`. Because the names + signatures match the imports, these collapse to ES2015 shorthand entries in the object literal (`createAccount,`) — each 3-line method → 1 line. The handful with arg reshaping (`sendMessage`, `saveDraft`, `deleteDraft`, `fetchReplyContext`, `fetchDraftContent`, `fetchConversationPage`→`fetchConversations`, `fetchOAuthRedirectUri`→`buildOAuthRedirectUri`, `fetchMessagePage`, `runMessageCommand`, `moveMessageToMailboxRole`) stay explicit. Medium risk because it relies on import/interface signatures staying aligned (a future shape drift would surface as a type error, which is acceptable).

### F6 — `runtimeMutations` is a third pure pass-through layer
- **category:** DUP (mutation plumbing)
- **file:** `runtime/mutations.ts:75-217`
- **EST_LOC_SAVED:** ~40 if the trivial leaves are collapsed; **0 recommended** without an architecture decision
- **risk:** med-high / behavior-change: n
- **how:** Account/mailbox/oauth/settings/smart-mailbox CRUD here are all `method(args) { return getRuntimeAdapter().method(args) }` — a third 1:1 layer on top of `httpAdapter` (F5) and `api/client` (the real impls). Three namespaces (`api/client` fns → `httpAdapter` methods → `runtimeMutations.*`) carry the same ~30 operations. Only `messages.command`/`moveToMailboxRole` add real logic (named-mutation routing + `confirmedMessageCommandResult`). The leaves *could* be generated, but the three-layer shape is load-bearing (transport-neutral facade + adapter swap for tests/entity-store). Flagging as the largest structural duplication; a real fix is "pick two of the three layers," which is a design decision, not a mechanical trim. Listed for visibility, **excluded from the headline total**.

### F7 — `runtime/fakeAdapter*` are test-only but live in `src/`
- **category:** BOILERPLATE / context-relocate
- **files:** `runtime/fakeAdapter.ts:1-377`, `runtime/fakeAdapterSupport.ts:1-379`, `runtime/fakeAdapterQueues.ts:1-116`
- **EST_LOC_SAVED:** 0 net (relocation, not deletion); 872 LOC out of the `src/` tree
- **risk:** low / behavior-change: n
- **how:** `createFakeRuntimeAdapter` and friends are imported **only** by `test/*` (13 test files), never by `src/`. They are 872 LOC of test scaffolding sitting in the production source tree, inflating the `runtime/` directory an AI loads as "the client." Move them under `test/support/` (or `apps/web/test/fakes/`). Pure tree-shake already keeps them out of the bundle; this is purely a context-hygiene move that makes `runtime/` 872 LOC smaller for a reader. (Total LOC unchanged — flagged, not counted.)

### F8 — Duplicated IndexedDB promise/connection plumbing in the two replica stores
- **category:** DUP
- **files:** `runtime/replica/outboxStore.ts:48-54` (`runRequest`) + lazy-connection cache; `runtime/replica/undoHistoryStore.ts` (its own request-wrap + connection cache)
- **EST_LOC_SAVED:** ~15
- **risk:** low / behavior-change: n
- **how:** Both modules re-implement `runRequest<T>(req): Promise<T>` (resolve `onsuccess` / reject `onerror`) and a lazy cached `openReplicaDatabase()` connection. They already share `replicaDatabase.ts`; move the `runRequest` helper + a `withStore(mode, fn)` transaction helper into `replicaDatabase.ts` and consume from both. Small but clean.

### F9 — `'native'` runtime mode is unreachable
- **category:** DEAD (latent)
- **files:** `connection/injected.ts:14,40`; `runtime/adapter.ts:90-92`
- **EST_LOC_SAVED:** ~5 (plus enables F4 to drop to a one-liner)
- **risk:** low / behavior-change: n
- **how:** `injectedRuntimeMode()` only ever returns `'loopback'`, `'native'`, or `undefined` from an injected global; `runtimeAdapterForMode` maps `'native'` to `unsupportedRuntimeAdapter`. No build injects `'native'`, so that branch (and the entire `unsupportedRuntimeAdapter`) is dead in practice. If `'native'` is confirmed unplanned, drop the mode from the union and delete the branch + the stub (compounds with F4). Verify with the desktop/embedded build config before removing.

### F10 — `viewDelta` frame plumbing is dead (entity store opens non-delta-capable)
- **category:** DEAD
- **files:** `components/message-list/useRuntimeMailListView.ts:50-81` (`applyDeltaToQueryData`) + `:232-256` (`case 'viewDelta'`); `runtime/types.ts` `RuntimeMailListDelta` + the `viewDelta` variant of `RuntimeFrame`
- **EST_LOC_SAVED:** ~45 (the component file is just outside the assigned dir set, but the `types.ts` portion is in-scope)
- **risk:** med / behavior-change: n
- **how:** Per `review-client-runtime-replica.md` §1, the only installed adapter (entity store) opens views non-delta-capable and synthesizes `viewReplace`; no `viewDelta` frame is ever emitted. The `viewDelta` case, `applyDeltaToQueryData`, `RuntimeMailListDelta`, and the `viewDelta` `RuntimeFrame` variant are dead. In-scope deletion is the `types.ts` `RuntimeMailListDelta` interface + `viewDelta` variant (~16 LOC); the rest needs the message-list owner to act. Medium risk: re-introducing delta views later would need this restored behind an explicit opt-in.

### F11 — `api/conformance/*` type-machinery is heavy but earns its keep
- **category:** VERBOSE (no action recommended)
- **files:** `api/conformance/core.ts:1-110`, `api/conformance/*.ts` (413 LOC total)
- **EST_LOC_SAVED:** 0 (do not trim)
- **risk:** — / behavior-change: —
- **how:** `core.ts` is ~110 LOC of recursive `Conforms`/`StructConforms` type gymnastics; the rest are `AssertTrue<...>` rows asserting the curated `api/types/*` match `schema.gen` `components['schemas']`. Emits no runtime code; exists to make `tsc` fail on wire drift. Verbose for a reader but it is the drift guard that lets the curated types stay small. Excluded from context like other type-only assertion files, but **not** a hand-trim target — deleting it removes the only check that `api/types` tracks the generated schema.

## Already done / not the opportunity the brief expected

- **TS fold reimplementation (review-unification §3.1–3.3).** Migrated. `entityStoreAdapter.ts` calls a WASM `EntityStoreHandle` for register/ingest/accept/settle/project and for `captureMutationDiffJson` + `invertMessageChangeDiff` (in `wasmUtil.ts`). The mutation-name→assertion mapping (`parseMessageMutation`) is also in WASM. The remaining TS is genuine orchestration (frame routing, outbox durability/rehydration/resend, React Query count writes), most of which exists for reasons documented inline (real shipped bugs: rehydration brick, absorption-retire, loadMore-vs-firehose race). Further reduction means pushing orchestration into WASM — **large, high-risk**, and not a mechanical LOC trim.
- **`entityStoreAdapter.ts` (730 LOC) is not bloat-by-duplication.** It is the single largest in-scope hand-written file, but it is one class with low duplication and dense doc-comments tied to regressions. Trimming the comments would save lines at the cost of the only record of why the races are handled the way they are — not recommended for an LOC-for-context goal where the comments *are* the context.
