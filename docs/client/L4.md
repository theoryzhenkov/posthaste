# Renderer runtime adapter migration patterns

## 1. Facade module pattern

`apps/web/src/runtime` is the only renderer module that may wrap mail HTTP client calls during the migration.

Pattern:

```text
runtime/types.ts       adapter contract and request types
runtime/httpAdapter.ts temporary HTTP-backed adapter
runtime/adapter.ts     active adapter selection and test override seam
runtime/fakeAdapter.ts backend-free test adapter
```

Components and hooks call `runtime/adapter` functions, not `api/client` mail reads or message commands, once a runtime operation exists.

## 2. HTTP bridge containment

The default adapter preserves production behavior by delegating to existing typed HTTP client functions. This is a bridge, not a component dependency.

Do not import HTTP mail functions from components for migrated paths such as message pages, message detail/conversation reads, navigation read calls, mailbox lookups, smart-mailbox summaries, or message commands.

Runtime resources are requested by descriptor and fetched as bytes through the adapter. Components do not build attachment/logo URLs and do not attach bearer headers. The HTTP adapter may translate descriptors to loopback URLs while the bridge exists.

Loopback connection details remain in the connection layer and the HTTP adapter. Desktop bootstrap injects runtime mode metadata so later adapter selection can switch away from loopback without changing component imports.

## 3. Fake adapter test pattern

Renderer tests use `createFakeRuntimeAdapter()` and `setRuntimeAdapterForTesting()` for migrated runtime paths. Tests should not start the backend or require injected loopback globals to exercise component behavior.

Queue fake results explicitly when the test cares about returned runtime state. The fake records calls so tests can assert user intent without coupling to URLs.

## 4. Compatibility wrapper pattern

Existing compatibility modules may remain as thin wrappers while call sites migrate:

```text
messagePageClient.fetchPage(request) -> fetchRuntimeMessagePage(request)
```

Keep these wrappers transport-neutral. Do not add URL building, auth headers, or endpoint-specific branching outside `runtime/httpAdapter.ts`.

## 5. Assertions

| ID | Sev. | Assertion |
| --- | --- | --- |
| runtime-module-owns-http-bridge | MUST | Temporary mail HTTP calls live behind `apps/web/src/runtime/httpAdapter.ts`. |
| migrated-components-use-runtime-adapter | MUST | Components and hooks use runtime adapter functions for paths that have migrated. |
| fake-adapter-no-backend | MUST | Renderer tests for migrated paths can run with `createFakeRuntimeAdapter()` and no backend startup. |
| compatibility-wrappers-thin | SHOULD | Legacy client wrappers delegate directly to the runtime adapter without transport logic. |
| resource-descriptors-not-urls | MUST | Components request runtime resources by descriptor and do not build HTTP attachment/logo URLs. |
| resource-auth-contained | MUST | Bearer headers for resource byte fetches stay inside the runtime HTTP adapter while the bridge exists. |
| desktop-mode-metadata | SHOULD | Desktop bootstrap exposes runtime mode metadata for adapter selection without exposing tokens to components. |
