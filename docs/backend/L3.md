# API runtime-wrapper implementation decisions

## 1. Migration shape

The `/v1` adapter migrates by branch-by-abstraction. `posthaste-server::AppState` now carries the target `AuthorityRuntimeHandle` while temporarily retaining the legacy fields used by existing handlers.

This preserves current endpoint behavior while enabling handlers to move one read, event, or command family at a time to runtime methods.

## 2. Startup assembly

`start_server` still owns HTTP process concerns: dotenv loading, daemon settings, logging, CORS, tracing, auth material, router assembly, Swagger UI, static asset serving, and listener binding.

Config/store/service/secret/event assembly moves to `posthaste-authority-runtime::build_authority_runtime`. `posthaste-server` reads daemon settings from TOML first because those settings are process/HTTP concerns needed before listener setup.

The current server cache root is `state_root/cache`. This follows the runtime L2 allowance that cache roots may be subdirectories of the state root, and keeps root resolution stable until a platform cache-root resolver is specified.

## 3. Temporary API bridge

`AuthorityRuntimeBuild` exposes `api_bridge` with existing `MailService`, `MailStore`, `SecretStore`, and event sender handles. This bridge is temporary and exists only for old route handlers.

`AccountSupervisor` remains constructed in `posthaste-server` during this wrapper phase because its implementation still depends on server OAuth/push modules and live provider wiring. Moving supervisor ownership into `posthaste-authority-runtime` is part of the removal criteria for the wrapper.

## 4. Test harness strategy

Most existing integration harnesses still seed stores and construct `AppState` directly. They use `AppState::runtime_handle_for_migration` to attach a runtime handle to the same service/store/event graph.

This keeps current tests focused on endpoint compatibility while preventing new API state from existing without a runtime handle.

## 5. Assertions

| ID | Sev. | Assertion |
| --- | --- | --- |
| appstate-runtime-plus-legacy | MUST | During migration, `AppState` carries `AuthorityRuntimeHandle` plus documented legacy fields. |
| startup-delegates-runtime-assembly | MUST | `start_server` delegates config, store, service, secret store, and event channel assembly to `posthaste-authority-runtime`. |
| server-keeps-http-process-concerns | MUST | Server startup keeps HTTP process concerns such as daemon settings, auth material, CORS, tracing, static serving, docs, and listener binding. |
| api-bridge-temporary | MUST | `AuthorityRuntimeBuild::api_bridge` is temporary and exists only for route handlers not yet moved to runtime methods. |
| supervisor-server-owned-temporary | MUST | `AccountSupervisor` may remain server-owned only during this wrapper phase. |
| harness-attaches-runtime | MUST | API integration harnesses that construct `AppState` directly attach a runtime handle through the migration helper. |
