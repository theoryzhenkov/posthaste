# API runtime-wrapper code patterns

## 1. Migration tag

Temporary wrapper code uses this exact tag:

```text
MIGRATION(api-runtime-wrapper)
```

Use it on direct legacy accessors, migration constructors, and bridge structs. Link nearby comments to the relevant SPECial assertion.

## 2. AppState pattern

`AppState` should expose the runtime handle first:

```rust
pub struct AppState {
    pub runtime: AuthorityRuntimeHandle,
    // legacy fields follow temporarily
}
```

New mail behavior should prefer `state.runtime`. Do not add new route-local service/store construction.

## 3. Server startup pattern

Startup uses the authority runtime builder before API adapter state:

```rust
let runtime_build = build_authority_runtime(
    AuthorityRuntimeBuildConfig::new(config_root, state_root, cache_root),
).await?;

let state = Arc::new(AppState {
    runtime: runtime_build.handle.clone(),
    service: runtime_build.api_bridge.service.clone(),
    // legacy fields continue temporarily
});
```

`posthaste-server` may still own HTTP process concerns: token root resolution, CORS/origin/host allowlists, tracing, static renderer serving, API docs, and listener binding.

## 4. Test harness pattern

Existing harnesses that manually assemble `MailService` and stores attach a runtime handle with:

```rust
runtime: AppState::runtime_handle_for_migration(
    service.clone(),
    store.clone(),
    secret_store.clone(),
    event_sender.clone(),
),
```

This is allowed only while the harness needs direct store seeding for API compatibility tests.

## 5. Fitness test pattern

Add small tests that prove the wrapper exists before migrating handler behavior:

```rust
let status = harness.runtime_status().await;
assert_eq!(status.lifecycle, RuntimeLifecycle::Ready);
```

Later handler migrations should add tests that fail if handlers bypass the runtime method introduced for that behavior family.

## 6. Assertions

| ID | Sev. | Assertion |
| --- | --- | --- |
| appstate-runtime-first | MUST | `AppState` declares the runtime handle before temporary legacy service/store fields. |
| migration-comments-searchable | MUST | Temporary wrapper code uses `MIGRATION(api-runtime-wrapper)` comments. |
| startup-builder-before-router | MUST | Server startup calls `build_authority_runtime` before constructing `AppState` and the router. |
| harness-runtime-helper | MUST | Direct AppState test harnesses use `AppState::runtime_handle_for_migration` rather than omitting the runtime handle. |
| no-route-local-runtime-graphs | MUST | Route modules do not construct new `MailService`, `DatabaseStore`, provider gateway, or supervisor graphs. |
