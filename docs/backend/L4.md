# API runtime-wrapper code patterns

## 1. Migration tag

Temporary wrapper code uses this exact tag:

```text
MIGRATION(api-runtime-wrapper)
```

Use it on direct legacy accessors, migration constructors, and bridge structs. Link nearby comments to the relevant SPECial assertion.

## 2. AppState pattern

`AppState` should expose the runtime handle first:

```rust
pub struct AppState {
    pub runtime: AuthorityRuntimeHandle,
    // legacy fields follow temporarily
}
```

New mail behavior should prefer `state.runtime`. Do not add new route-local service/store construction.

## 3. Server startup pattern

Startup uses the authority runtime builder before API adapter state:

```rust
let runtime_build = build_authority_runtime(
    AuthorityRuntimeBuildConfig::new(config_root, state_root, cache_root),
).await?;

let state = Arc::new(AppState {
    runtime: runtime_build.handle.clone(),
    service: runtime_build.api_bridge.service.clone(),
    // legacy fields continue temporarily
});
```

`posthaste-server` may still own HTTP process concerns: token root resolution, CORS/origin/host allowlists, tracing, static renderer serving, API docs, and listener binding.

## 4. Runtime read handler pattern

A read-only route that has a runtime method should call `state.runtime` and pass an adapter-neutral caller:

```rust
state
    .runtime
    .get_app_settings(RuntimeCaller::api())
    .await
    .map(Json)
    .map_err(ApiError::from_runtime_error)
```

Do not read the same state from `state.service` once a runtime method exists for that read.

## 5. Account scope pattern

Account-scoped reads use runtime-owned scope requests:

```rust
state
    .runtime
    .list_mailboxes(
        RuntimeCaller::api(),
        AccountScopeRequest::EnabledAccounts,
    )
    .await
```

or:

```rust
AccountScopeRequest::Explicit { account_ids }
```

API adapters must not derive default enabled-account scope by calling account-list and filtering the response payload. Use `resolve_account_scope` or pass `AccountScopeRequest` directly to the read method.

## 6. Provider-backed read pattern

Provider-backed reads should expose a runtime method first, then route through it:

```rust
state
    .runtime
    .get_identity(RuntimeCaller::api(), account_id)
    .await
    .map(Json)
    .map_err(ApiError::from_runtime_error)
```

The runtime implementation uses `LiveAccountRuntimeProvider` to reach the authority-runtime `AccountSupervisor`; route handlers should not call `live_gateway` once a runtime method exists.

## 7. Runtime error mapping pattern

Runtime errors crossing `/v1` use `ApiError::from_runtime_error`. The mapper preserves the runtime error message/details and maps runtime error codes into existing API status/code pairs.

This is a temporary compatibility mapper until route families have more specific API/runtme error contracts.

## 8. Test harness pattern

Existing harnesses that manually assemble `MailService` and stores attach a runtime handle with:

```rust
runtime: AppState::runtime_handle_for_migration(
    service.clone(),
    store.clone(),
    secret_store.clone(),
    event_sender.clone(),
),
```

This is allowed only while the harness needs direct store seeding for API compatibility tests.

## 9. Fitness test pattern

Add small tests that prove the wrapper exists before migrating handler behavior:

```rust
let status = harness.runtime_status().await;
assert_eq!(status.lifecycle, RuntimeLifecycle::Ready);
```

For migrated reads, compare the HTTP route output with the same projection read through `Harness::runtime_*`.

Later handler migrations should add tests that fail if handlers bypass the runtime method introduced for that behavior family.

## 10. Architecture guard pattern

`runtime_wrapper.rs` scans non-test route-module source files for forbidden graph constructors:

```rust
["MailService::new", "DatabaseStore::open", "AccountSupervisor::new"]
```

This guard allows test harnesses to keep constructing seeded graphs while preventing new runtime graphs in route implementations.

## 11. Assertions

| ID | Sev. | Assertion |
| --- | --- | --- |
| appstate-runtime-first | MUST | `AppState` declares the runtime handle before temporary legacy service/store fields. |
| migration-comments-searchable | MUST | Temporary wrapper code uses `MIGRATION(api-runtime-wrapper)` comments. |
| startup-builder-before-router | MUST | Server startup calls `build_authority_runtime` before constructing `AppState` and the router. |
| harness-runtime-helper | MUST | Direct AppState test harnesses use `AppState::runtime_handle_for_migration` rather than omitting the runtime handle. |
| no-route-local-runtime-graphs | MUST | Route modules do not construct new `MailService`, `DatabaseStore`, provider gateway, or supervisor graphs. |
| runtime-read-handler-pattern | MUST | Routes with runtime read methods call `state.runtime` with `RuntimeCaller::api()`. |
| account-scope-request-pattern | MUST | Account-scoped runtime reads use `AccountScopeRequest` rather than API-side account-list filtering. |
| provider-backed-read-pattern | MUST | Provider-backed read handlers call runtime methods and let runtime-owned providers resolve live gateways. |
| runtime-error-to-api | MUST | Runtime errors crossing HTTP are mapped through `ApiError::from_runtime_error`. |
| migrated-read-compat-test | MUST | Migrated read routes have compatibility tests comparing HTTP output with runtime output. |
| route-constructor-guard | MUST | A route-module guard rejects new direct service/store/supervisor constructors outside tests. |
