## 1. What is built and verified

The portable, side-effect-free core of the client-layer replica is implemented and tested natively, and verified to compile to `wasm32-unknown-unknown`:

- **`posthaste-link-core`** — the shared predictor (`MessageFoldState`, `MessageAssertion`, `replay`, coalescing) and the convergence engine (`MessageReplica`: accept / `apply_base_update` / `settle` / `project`). `posthaste-domain` uses the predictor for its overlay fold (single-local-effect). Retirement is per-mutation settlement.
- **`posthaste-link-replica`** — the working-set view layer (`MailListReplica`): ingest served rows as the base, fold the outbox over them, project optimistic rows with a membership predicate.
- **`posthaste-link-wasm`** — the `wasm-bindgen` boundary (`MailListReplicaHandle`: `ingestJson` / `acceptJson` / `settle` / `projectJson`), values crossing as JSON strings. `cargo check` passes for `wasm32` and native.

**Environment gaps that bound the rest (not code problems):** the final cdylib `.wasm` link needs a wasm linker (`rust-lld`); generating the JS/`.d.ts` bindings needs `wasm-bindgen-cli`; W4/W5 need a bundler, a browser, and a running hosted runtime. The steps below are specified against the verified crate APIs.

## 2. The wasm boundary

`MailListReplicaHandle` is the only JS-facing surface, deliberately narrow:

- `new()` — construct a replica for one mail-list view.
- `ingestJson(rowsJson)` — adopt a served base: a JSON array of `{ messageId, projection }`.
- `acceptJson(json)` — accept an optimistic mutation: `{ mutationId, messageId, assertion }`, where `assertion` is `{kind:"setKeywords",add,remove}` | `{kind:"replaceMailboxes",mailboxIds}` | `{kind:"destroy"}`.
- `settle(mutationId, "confirmed"|"failed") -> bool` — retire a pending mutation; `true` means a failure reverted optimism (surface it).
- `hasPending() -> bool`, `projectJson(mailboxId?) -> string` — the optimistic rows in served order; pass the view's concrete mailbox to drop archived-out rows, omit it to defer membership to the runtime.

JSON-string passing keeps the dependency to `wasm-bindgen` alone and makes the type contract explicit and inspectable. The handle is pure compute: no transport, no storage.

## 3. Packaging (W3 integration)

Build the cdylib for `wasm32-unknown-unknown` and run `wasm-bindgen-cli` (or `wasm-pack`) to emit the JS loader + `.d.ts`. Integrate into `apps/web` via a Vite wasm plugin so the module loads in the worker/main thread. The release web build (the `bun --cwd=apps/web run build` steps) gains a wasm build+bindgen step gated to when the replica is enabled. Keep `posthaste-link-wasm` excluded from native CI (already done); add a wasm build job that runs `cargo build --target wasm32 -p posthaste-link-wasm` + bindgen.

## 4. IndexedDB persistence

The replica's durable state is the **outbox**; the base/rows cache is rebuildable.

- **Object store `outbox`** — keyed by `mutationId`; value `{ messageId, assertion, clientMutationId, runtimeMutationId?, acceptedAt }`. Idempotent on key (re-accept is a no-op). Versioned/migrated, never silently dropped (it is the only home of unconfirmed intent).
- **Object store `base`** — per open view, the last served rows (`{ messageId, projection }[]`) so a reload re-renders instantly before the down-channel resumes. Rebuildable: on version skew or corruption, drop and re-acquire by snapshot.

On load: rehydrate `outbox` into the handle (replay `acceptJson` for each), then open views and `ingestJson` the cached base (if any) before the live stream catches up.

## 5. Transport injection and the contract↔replica mapping

The JS host owns transport (it reuses what `httpAdapter` already does against the remote runtime API):

- **Up-channel.** A renderer mutation → mint a `ClientMutationId`, `acceptJson` it into the handle, persist to the `outbox` store, and `POST` the named mutation to the runtime. Record the returned `MutationReceipt` (`clientMutationId` ↔ `runtimeMutationId`).
- **Down-channel.** Subscribe to the runtime's frame stream (`/v1/.../stream`, the existing SSE). Map frames to the handle:
  - `ViewSnapshot` / `ViewReplace` → `ingestJson` of `snapshot.data.rows` mapped to `{ messageId, projection }`. `messageId` comes from `row.resourceRef` (`message:{src}:{id}`) or `row.projection.id`; `projection` is `row.projection` as-is.
  - `MutationSettlement { mutationId, state }` → `settle(clientMutationId, …)` (translate via the receipt map): `Confirmed` → `"confirmed"`; `Failed`/`Conflict` → `"failed"` (surface). `Accepted`/`LocalApplied`/`Queued` are non-terminal — ignore.
- **Membership for `projectJson`.** Extract the view's concrete mailbox from `MailListViewState.scope.query` when the query is a single-mailbox filter, and pass it so archived-out rows drop instantly. For smart/compound queries pass no mailbox: those rows are corrected by the next served base (full local query evaluation is the deferred coverage/atoms layer, not this one).

## 6. The replicaAdapter (W4)

A third `RuntimeAdapter` implementation (`apps/web/src/runtime/replicaAdapter.ts`) backed by the wasm handle + the transport/persistence above, selected behind `VITE_RUNTIME_REPLICA` (default off) alongside `httpAdapter`. The renderer is unchanged (`runtime-adapter-opaque`): the adapter still answers `openRuntimeSession*`, `open/extend/closeView`, `runRuntimeMutation`, and the frame subscription — but a `mailList` view's frames are now produced **locally** by `projectJson` after each `accept`/`settle`/`ingest`, while non-replicated surfaces still pass through. Parity tests assert the replica adapter yields the same observable frames as `httpAdapter` for the covered flows.

## 7. Hardening (W5)

- **Snapshot recovery.** On a down-channel gap, re-`open` the view (fresh snapshot) and `ingestJson`; the outbox re-folds. Reconcile the outbox against the recovered `pendingMutations` only for mutations the runtime has acknowledged (by receipt), never dropping not-yet-forwarded local ones.
- **Never-confirms backstop.** Retire an accepted-but-never-settled mutation after a bounded number of convergence cycles; record telemetry.
- **Entity convergence.** Drafts/sends reconcile a provisional id to the assigned id (the `X-Posthaste-Draft-Id` stable key for drafts; the receipt's `runtimeMutationId`/assigned id for sends); dedupe by authoritative id so a provisional row and its confirmed row never both show.
- **Multi-window.** Tab-local replicas to start; a `SharedWorker`-backed single replica is the path to cross-tab coherence if needed.
- **Dogfood** behind the flag before default-on.

## 8. Assertions

| ID | Sev. | Assertion |
| --- | --- | --- |
| wasm-boundary-json | MUST | The replica's only JS surface is `MailListReplicaHandle` over JSON-string values; it performs no transport or storage itself. |
| outbox-indexeddb-durable | MUST | The outbox persists in IndexedDB keyed by mutation id, survives reload, and is migrated (never silently discarded); the base cache is rebuildable by snapshot. |
| settlement-via-receipt | MUST | The host translates `MutationSettlement` to `settle` through the `ClientMutationId`/`RuntimeMutationId` pairing recorded from the `MutationReceipt`. |
| replica-adapter-flagged | SHOULD | `replicaAdapter` is selected behind `VITE_RUNTIME_REPLICA`, default off, until dogfood promotes it; the renderer is unchanged when it is selected. |
