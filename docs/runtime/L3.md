# Runtime extraction implementation decisions

## 1. First-slice scope

The first implementation slice establishes the runtime crate seam required before server and desktop adapters can share mail behavior.

It creates two crates using the names recommended by the L2 runtime and backend specs:

- `crates/posthaste-runtime-contract`
- `crates/posthaste-authority-runtime`

This slice does not use the temporary single-crate fallback.

## 2. Shared runtime contract

`posthaste-runtime-contract` owns adapter-safe runtime types and the first `RuntimeCore` trait.

Concrete choices:

- `RuntimeCore` is an async trait so future view, mutation, event, and resource methods can perform runtime work without changing trait style.
- The first method is `runtime_status(RuntimeCaller) -> RuntimeStatus` because the test-plan seam requires building an authority handle and reading startup/runtime status.
- Runtime IDs are opaque string newtypes: `RuntimeSessionId`, `ViewId`, `SubscriptionId`, `ClientMutationId`, and `RuntimeMutationId`.
- Runtime revisions use a numeric `ViewRevision` newtype.
- Contract payloads serialize with camelCase fields unless the spec requires another convention.
- The adapter error envelope is `RuntimeAdapterError { code, message, retryable, correlationId, details }` with the initial code catalog from `docs/runtime/L2.md`.

The contract crate must not depend on Axum, Tauri, React/frontend packages, provider clients, SQLite table types, or replica-table types.

## 3. Authority runtime builder

`posthaste-authority-runtime` exposes `build_authority_runtime(AuthorityRuntimeBuildConfig) -> AuthorityRuntimeBuild`.

Concrete choices:

- `AuthorityRuntimeBuildConfig` accepts already resolved `config_root`, `state_root`, and `cache_root` paths.
- Empty config roots are initialized with default config and smart mailboxes, or imported from `bootstrap_path` when supplied.
- The builder opens `DatabaseStore` at `state_root/mail.sqlite` and uses `state_root` as the store data root.
- The builder constructs `MailService`, syncs source projections, creates a runtime event broadcast channel, and records the configured account count in startup status.
- Production callers can use the default `SystemSecretStore`; tests can pass an injected `SecretStore` implementation for the mock-secret-store seam required by the test plan.
- The build output is `AuthorityRuntimeBuild { handle, shutdown, runtime_status }`.

The builder is transport-free: it does not bind a listener, build an Axum router, create Tauri windows, or expose transport handles in runtime method signatures.

## 4. Runtime status and shutdown seam

`RuntimeStatus` intentionally reports only adapter-safe readiness fields:

- lifecycle state
- config/store/cache readiness booleans
- configured account count

It does not expose filesystem roots, provider secrets, bearer tokens, SQLite handles, or keyring references.

`RuntimeShutdownHandle` is present in the first slice even though account runtimes, view subscriptions, and queued mutation workers are not extracted yet. The handle marks the runtime stopped so adapters and tests depend on the runtime-owned shutdown seam from the beginning.

## 5. Deferred extraction

The following remain outside the first slice and should be implemented through later L2 test-plan sections:

- account supervisor ownership in `posthaste-authority-runtime`
- API adapter state wrapping the runtime handle
- renderer runtime adapter facade
- view registry and `MailListViewState` runtime service
- mutation coordinator and durable idempotency records
- runtime resource resolver and scoped resource capabilities

## 6. Assertions

| ID | Sev. | Assertion |
| --- | --- | --- |
| runtime-contract-crate-name | MUST | The first runtime contract crate is `posthaste-runtime-contract`, not a module inside `posthaste-server`. |
| authority-runtime-crate-name | MUST | The first authority runtime crate is `posthaste-authority-runtime`, not a module inside `posthaste-server`. |
| status-first-runtime-core-method | MUST | The first `RuntimeCore` method reads runtime status through adapter-neutral `RuntimeCaller`. |
| builder-roots-pre-resolved | MUST | Authority runtime build inputs receive pre-resolved config, state, and cache roots. |
| status-no-sensitive-fields | MUST | Runtime status does not expose filesystem roots, provider secrets, bearer tokens, SQLite handles, or keyring references. |
