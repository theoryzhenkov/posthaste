## Foundations for split deployments

This is an internal-foundations release: the app behaves exactly as in 0.1.81 —
the default bundled setup is byte-for-byte unchanged.

### Under the hood

- **The runtime↔backend boundary is now a real, switchable link.** The runtime
  reaches the backend through a transport that defaults to in-process (identical
  to before) but can be pointed at a remote backend. When it is, the runtime
  forwards changes optimistically and serves reads from a coherent read-through
  cache, fetching from the backend only on a miss and keeping cached entries
  fresh from the backend's change stream.
- This is the groundwork for running the backend and the runtime on separate
  machines, and for each layer holding its own cache — no user-facing change yet.
