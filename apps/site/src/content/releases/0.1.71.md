## Steadier actions and accounts

This build hardens the local-first action system from the last release and fixes
three rough edges that showed up while dogfooding.

### Fixes

- **The settings pane no longer hijacks the window.** Flagging, archiving, or
  moving a message could momentarily flip the app into account settings while
  the change settled. The UI no longer reacts to that transient state.
- **Accounts no longer get stuck "syncing."** A dropped status update could
  strand an account in the syncing state until you pressed sync manually.
  Runtime status is now written atomically so it always lands on a final state.
- **No more flicker when you act on a message.** Optimistic changes (flags,
  moves) could briefly snap back to the old value before re-applying, because a
  pending change was cleared before the synced mailbox caught up. Pending
  changes now retire only once the server's truth has converged, so the
  displayed value never bounces.
- Automation rules that run after an action now reconcile cleanly instead of
  leaving queued follow-up work behind.

### Under the hood

- Message actions (flag, read, tags, archive, trash, move, delete) now run
  through a single runtime mutation pipeline — the groundwork for runtime-owned
  undo/redo and live, server-folded views. These newer paths are staged behind
  flags and not yet active in this build.
