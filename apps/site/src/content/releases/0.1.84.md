## Faster mail-list updates

Acting on a message — flagging, marking read, archiving — now updates the list
by sending only the rows that changed, instead of re-sending the whole list on
every change. The bigger the mailbox, the more this saves, on both ends of the
connection.

### Under the hood

- **Incremental view updates.** The runtime→client link now carries per-row
  mail-list deltas rather than whole-view snapshots for in-list changes, and the
  client reconciles them in place. The full view is still sent only for the
  cases that genuinely replace it — initial load, paging, and filter changes —
  so behavior is unchanged; just the wire and the work shrink.
- **The split-deployment foundation is now runnable.** The runtime reaches the
  backend entirely through one authenticated link, so it can run as a pure near
  node with no local backend, and a standalone backend binary serves that link.
  A remote runtime keeps its lists live from the backend's change stream.
- The default bundled setup is unchanged — same app, lighter list updates.
