## More groundwork for split deployments

Another internal-foundations release: the app behaves exactly as in 0.1.82 —
the default bundled setup is unchanged.

### Under the hood

- **The backend now builds as a standalone far node**, separate from the
  runtime that sits in front of it — the seam that will let the backend and the
  runtime run as their own processes (and eventually their own installable
  binaries).
- **One contract for the backend boundary.** The runtime reaches the backend
  through a single `BackendApi` — forwarding changes up and reading through a
  cache that, when the backend is remote, keeps itself fresh from the backend's
  change stream and serves what it has fetched locally. Co-located, that cache
  is a transparent pass-through, so nothing changes today.
- Recorded the plan for a future control plane that lets you choose where each
  layer runs — no user-facing change yet.
