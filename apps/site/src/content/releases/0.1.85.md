## Snappier message actions

Acting on a message — flagging, marking read, archiving, moving — now updates
the list right away, even in large mailboxes. The last release made the _update_
that goes over the wire incremental; this one fixes the work the runtime did to
produce it.

### Under the hood

- **Mail-list views recompute from an indexed query, not a full scan.** Acting on
  one message used to make the runtime load every message in the mailbox, fold
  pending changes over all of them, sort them in memory, and keep the top 50 —
  work proportional to the whole mailbox, on every change. It now serves the page
  straight from an indexed query, work proportional to the page. In our benchmark
  a single action's recompute dropped ~23×, and the bigger the mailbox the larger
  the win.
- **Optimistic changes live in the local store now.** Your action is written
  through to the local database immediately and reconciled against the provider's
  authoritative reply, so the list reflects the change at once and converges to
  the server's truth — reverting cleanly if the server rejects it. Incoming sync
  no longer clobbers a change that is still in flight.
- **Concurrent actions on one message no longer interfere.** Flag-then-archive
  before the first confirms now settles without the row flickering back.
- The default bundled setup is unchanged — same app, faster actions.
