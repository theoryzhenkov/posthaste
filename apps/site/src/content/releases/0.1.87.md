## Live updates that heal themselves

When mail arrives or changes elsewhere, the app keeps its views current over a
live stream from the in-app runtime. That stream could quietly drop — most often
right after a batch of messages landed at once, or when the in-app connection
hiccuped — and live updates would simply stop until you reloaded the window. This
release makes that stream self-healing, so updates keep flowing on their own.

### Under the hood

- **The live update stream reconnects automatically.** If the connection to the
  in-app runtime drops, the client now reopens it and catches up to the current
  state, instead of going silent until a manual reload. (Covered by a new
  regression test.)
- **Bursts no longer overrun the update channel.** The runtime's per-session
  update buffer is larger, and a momentary overflow now recovers by re-sending
  the current state rather than tearing the stream down.
- **The runtime can finally explain itself.** It had no logging of its own (and
  the log filter had gone stale after the recent split into separate binaries),
  so update-delivery problems were invisible. It now logs stream lifecycle and
  warns when an update burst overflows — so the next issue leaves a trail.
- **Removed an unused internal endpoint** (`/v1/events`); the live path goes
  through the runtime session stream, so this was dead surface.
- The default bundled setup is unchanged — same app, steadier live updates.
